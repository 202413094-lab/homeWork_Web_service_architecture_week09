# WEEK 09 실습 2 · 검색·정렬·페이지네이션 게시판

Node.js와 Express로 1,000건의 인메모리 게시글을 검색하는 실습이다. 오프셋 모드에서는 페이지 번호로 이동하고, 커서 모드에서는 검색 결과를 ID 내림차순으로 이어서 불러온다.

## 실행 방법

Node.js와 npm이 설치된 환경에서 저장소를 내려받고, `server.js`가 있는 폴더에서 다음 명령을 실행한다.

```bash
npm install
node server.js
```

터미널을 열어 둔 상태에서 브라우저로 [게시판](http://localhost:3000)에 접속한다.

## 원본과 비교해 수정한 부분

| 파일 | 원본 동작 | 수정 내용 |
| --- | --- | --- |
| `server.js` | 정렬 키를 객체에서 바로 조회해 `constructor` 같은 상속 속성도 선택될 수 있었다. | `Object.hasOwn()`으로 직접 등록된 `latest`, `oldest`, `views`만 허용한다. 그 밖의 값은 `latest`로 처리한다. |
| `server.js` | 최신순과 오래된순이 게시글 ID만 비교해 실제 작성일 순서와 어긋났다. | `createdAt`을 먼저 비교한다. 날짜가 같으면 최신순은 큰 ID부터, 오래된순은 작은 ID부터 표시한다. |
| `server.js` | 커서 API는 이전 ID 다음에 올 게시글을 찾을 때 검색어를 반영하지 않았다. | 커서 조건을 적용한 목록에서 제목 또는 본문에 검색어가 포함된 글을 고른 뒤, 기존 `limit + 1` 방식으로 다음 결과가 있는지 판단한다. |
| `index.html` | 커서 요청에서 검색어가 빠졌고, 커서 탭 이름만으로는 정렬 기준을 알기 어려웠다. | 첫 조회와 ‘더 보기’ 요청에 `search`를 전달하고 탭에 ‘ID 내림차순 고정’을 표시한다. |

## 실행 결과 확인

- **정렬 키** — `wrong`, `__proto__`, `constructor`로 각각 요청했을 때 첫 세 글이 최신순과 같은 973번, 945번, 917번으로 표시됐다.
- **커서 제목 검색** — `B-Tree`를 검색하면 첫 세 글이 1000번, 988번, 976번 순서로 표시된다. ‘더 보기’를 누르면 같은 검색어를 유지하면서 이전 목록의 마지막 ID보다 작은 글을 불러온다.
- **검색어 변경과 마지막 페이지** — 검색어를 `1000번의 상세 본문`으로 변경했을 때 이전 목록이 사라지고 1000번 글만 표시됐다. 응답은 `cursor: null`, `hasNext: false`였으며 ‘더 보기’가 비활성화됐다.
